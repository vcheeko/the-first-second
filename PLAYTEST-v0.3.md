# v0.3 Play-test Gate

Do not advance to v0.4 until the browser prototype has been opened and the results below are reviewed.

## Technical check

- [ ] `prototype/index.html` opens without a build step.
- [ ] Master time advances once per second.
- [ ] Player seconds count down independently.
- [ ] `−10 s`, `−50 s`, pause/resume, and reset work.
- [ ] No obvious JavaScript/runtime error interrupts the experiment.

## Mechanics check

- [ ] High seconds feel stable rather than merely "healthy".
- [ ] Falling seconds visibly change the relationship to local reality.
- [ ] The unstable state is understandable without a long explanation.
- [ ] Metaphase feels like a state change rather than ordinary damage.
- [ ] The light/information state suggests a different form of existence.
- [ ] A possible simulation boundary becomes perceptible at low seconds.
- [ ] `0 seconds` does not read as an automatic conventional game-over.

## Design questions to record

1. What was the first moment that felt like reality itself was changing?
2. Did fewer seconds feel only negative, or also like access to something new?
3. Was the distinction between master time and player seconds understandable?
4. Did the state names help or reveal too much too early?
5. Should the first anomaly happen earlier or later?
6. What should the player be able to *do*, not only observe, near the boundary?

## Gate rule

If the prototype fails the technical check, fix v0.3 first.

If it runs but the mechanic is unclear, revise v0.3 before adding identity/memory complexity.

Only after the core inversion is legible should v0.4 begin.
